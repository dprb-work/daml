# Consume generated schema modules in browser applications

## Why

Consumers already derive JSON Schema from their own type systems. Python can admit those modules, but the browser SDK only accepts native definition bundles. Requiring a second native-definition generator duplicates schema ownership.

Existing shape validators also need to check supplied values without applying DAML defaults or constructing absent containers. Resolution cannot substitute for that operation without changing acceptance behavior.

## What Changes

- Add browser admission and composition of explicit JSON Schema module strings through the existing core registry.
- Expose constraint-only semantic validation in the core, Python binding and browser SDK.
- Support bounded structural schema recursion, including recursive resources, finite default completion and pre-engine validation-work accounting; continue rejecting non-progressing reference loops.
- Preserve all existing resource bounds, closed resource lookup, structured failures and owned-handle behavior.
- Preserve existing acyclic completion, source grammar and semantic writing. Recursive completion uses the same bounded failure behavior rather than inventing leaves.

The user authorized this cross-project integration and ownership split. This change supplies generic DAML capabilities; the consuming project owns type export, reachable resources and application construction policy.

The scope owner additionally confirmed structural recursion as a required
capability after real consumer qualification found legitimate nested generator
contracts rejected by the original acyclic profile. This changes the generic
schema profile; it does not authorize a consumer-specific workaround.

## Capabilities

### New Capabilities

- `browser-schema-modules`: Admit consumer-generated JSON modules without native-definition lowering or network discovery.
- `semantic-validation`: Validate supplied values and assertions without completion or mutation.
- `recursive-schemas`: Preserve finite recursively nested data contracts with bounded validation and completion.

### Modified Capabilities

- The generic schema profile now admits structural recursion instead of rejecting every cycle. Existing acyclic resolution and serialization contracts remain in force.

## Impact

Production changes stay in the existing schema/resolution owner and thin Python/browser bindings. Browser TypeScript declarations are generated by the existing build command. Independent checks cover real native/browser parity and Python behavior.

This change does not add application-specific selectors, reference policies, dependencies, a new schema format, a second validator, hosted CI spending, or release authorization.
